# TradeTwin Functional Audit

Verified on 2026-09-08. This audit preserves the existing workflows and demo scope;
it is not a guarantee that every possible input or deployment is defect-free.

## Fixes

- Browser API calls use an allowlisted same-origin proxy. Runtime service URLs
  work in Docker without embedding container hostnames or localhost ports in the browser.
- Standard compliance actions use uploaded evidence. Explicit demo-document actions
  remain available without silently supplying certificates to normal evaluations.
- Rule evaluation respects effective dates and version precedence, saved question
  answers, and unsupported-jurisdiction coverage. Empty rules cannot imply compliance.
- The sealed-onboard answer is evaluated by a versioned demo handling rule, without
  treating transit cargo as an import. Invalid question answers and date ranges are rejected.
- Regulation impact assessments persist evidence. Each evaluated rule has a ledger
  entry even when it has no matching document or shipment event.
- Only fully compliant route options are recommended. Empty shipments are handled.
- Historical shipment events replay chronologically; transit arrivals preserve
  already imported consignments. Duplicate leg sequences and invalid inputs are rejected.
- Failed Neo4j projection updates and deletions persist as retry tasks in PostgreSQL.
  Readiness checks retry pending tasks; database state remains the source of truth.
- Uploads support all document types required by the demo rules. Empty, unsupported,
  oversized files (over 20 MiB), and unsafe shipment path identifiers are rejected.
- Extraction triggers reevaluation and refreshes evidence. Upstream evidence failures
  are surfaced instead of silently appearing successful.
- Missing LLM credentials use the labeled mock provider; provider failures return
  a recoverable API error. Synthetic risk predictions retain their warning.
- Dashboard module shortcuts, active shipment filtering, regulation version listing,
  access-token controls, and narrow-screen navigation were repaired.
- Backend dependency readiness, Compose health checks, CI tests, and integration
  scripts were expanded. Long report text and validation-error serialization were fixed.

## Repeat Checks

Install backend requirements into a Python virtual environment first. From the root:

```powershell
python -m pytest -q
python -m ruff check apps/api services scripts
python scripts/smoke-test.py --local
python scripts/smoke-test.py --local --infrastructure
```

The infrastructure variant requires the infrastructure containers and credentials
from `.env` (falling back to `.env.example`). It creates and removes isolated audit
resources. Local service ports 18000 and 18011-18014 must be free.

From `apps/web`, run `npm ci`, `npm test`, `npm run lint`, and `npm run build`.
For browser checks, install Python Playwright and Chrome, start the built frontend
on port 3100 with runtime service URLs pointing to the audit ports, then run
`python scripts/smoke-test.py --local --infrastructure --browser` from the root.
Screenshots are saved to the ignored `artifacts/audit/` directory.

## Runtime Configuration

The frontend server reads `SHIPMENT_SERVICE_URL`, `COMPLIANCE_SERVICE_URL`,
`DOCUMENT_SERVICE_URL`, `INTELLIGENCE_SERVICE_URL`, and `API_SERVICE_URL`.
Compose supplies internal service addresses. Browser requests use `/api/services/`.
Explicit `NEXT_PUBLIC_*` overrides remain build-time settings.

`/health` is liveness; `/ready` checks enabled dependencies on the four domain services.
When demo authentication is enabled, use the account menu to supply an existing
configured demo access token. This is not user registration or production identity management.

## Remaining Boundaries

- Rules, tariffs, treaty assumptions, taxonomy, and scenarios remain demo data.
  Risk predictions are synthetic; the default LLM is mocked. No legal accuracy is implied.
- PDF extraction is text-based, not advanced OCR. Scanned documents need another process.
- Authentication remains the existing compliance-service demo RBAC implementation,
  not comprehensive protection of every service or production tenant isolation.
- Dashboard fallback aggregates remain a mix of live and demo data. The API gateway
  and shared/domain scaffolds are intentional extension points, not completed business services.
- The retry mechanism is suitable for this local prototype; concurrent distributed
  writers and production failure recovery require further hardening and load testing.
- Rebuild the deployment to run the updated source. No Git commit or push was performed.

```powershell
docker compose up -d --build
docker compose ps
powershell -ExecutionPolicy Bypass -File scripts/health-check.ps1
```

Open http://localhost:3000. Do not use `docker compose down -v` unless you intend
to delete persistent application data.
